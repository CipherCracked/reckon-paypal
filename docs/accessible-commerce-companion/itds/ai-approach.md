# Accessible Commerce Companion — ITDs

| ITD 2 — *"Use deterministic code for every figure and the model only for language and extraction."* |  |
| :---- | :---- |
| **THE PROBLEM** | The product turns merchant copy and order data into language a shopper can judge. Arithmetic cannot be delegated to a language model: one wrong total ends the product's usefulness, and models produce confident wrong numbers. |
| **OPTIONS CONSIDERED (Decision in bold)** | 1. **Code computes all monetary values; the model reads product text and terms, labels charges, and drafts the restatement.**<br>2. The model performs the arithmetic as well.<br>3. Rules and templates only, with no model.<br>4. The model with a calculator tool. |
| **REASONING** | The split follows the failure mode. Arithmetic has a verifiable answer, so it belongs in code where it can be tested. Language has no single answer and varies per merchant, so it belongs to the model. Option 2 breaks the core promise. Option 3 cannot read the range of merchant copy a real checkout carries. Option 4 still leaves the model choosing which numbers matter, so a wrong mapping remains possible. |
| **TRADEOFFS** | Two components to coordinate, and model output must be constrained so it never states a figure the code did not produce. The response contract needs guarding. |
| **NOTES** | Model choice is deferred; the binding constraint is a structured contract where monetary values are supplied to the model, never generated by it. |
