# ITD 19 — Pairing a Figure With Its Sentence

**Status:** Adopted (2026-11-10) — **built (2026-11-10)**
**Date:** 2026-11-10
**Answers:** Problem tree Q2 of `../intro.md` — *how is a seller's sentence shown beside the figures it produced*.
**Serves:** IPD 21, which cannot put a sentence and a figure in the same view unless the figure carries the sentence.

| *"Carry the verified span on the figure it produced, and render it where the figure is."* |  |
| :---- | :---- |
| **THE PROBLEM** | Figures and their evidence have different shapes in different places. `RenderedFigure` (`lib/commitment/present.ts:13`) carries an id, a label, an amount and an arithmetic string — no source. The consent payload carries one quote, `quotedExit`, for the exit figure only, and it is a `{ source, span }` produced after `resolveExitTerm`, not a property of the figure. The document reader already returns `sources` keyed by figure id (`lib/document/read.ts:19`, `Record<FigureId, string | null>`), which is the shape this decision generalises — the gap is the commitment, bill and receipt paths, not the document path. So a screen that wants to place "the seller wrote this" next to "we worked out that" has to join two structures by convention in each component, and the entry has no join at all. Nothing about a figure says which sentence produced it, which is why IPD 21's two-column view cannot be built without changing the figure's shape. |
| **OPTIONS CONSIDERED (Decision in bold)** | 1. **`RenderedFigure` gains an optional `source: { label, span } \| null`; it is populated only from a span that survived verification, and `null` means this figure was not read from a sentence.**<br>2. Return a separate `sourcesByFigure` map beside the figures and join it at each render site.<br>3. Put the quoted sentence into the existing `arithmetic` string.<br>4. Render the sentence only for the exit figure, as today, and let the other figures stand alone. |
| **REASONING** | A figure and the evidence for it are one claim, and a claim is easier to keep honest when it travels as one object. Option 2 works until the third render site: the figures array and the sources map can be sent to different components, filtered differently, or reordered, and nothing fails — the sentence simply disappears or attaches to the wrong figure. Option 1 makes that impossible: a figure either carries its sentence or carries `null`. Option 3 is the one that looks cheapest and is wrong in kind: `arithmetic` states what the *code* computed ("12 × $12.00"), and a quotation states what the *seller* wrote. They are different evidence from different authors, and a screen that merges them makes the model's reading look like our arithmetic — the exact confusion the product exists to remove. Option 4 is the current state and is what IPD 21 exists to correct. `null` must be distinguishable from "we did not look": the field is populated by the code that performed the read, so a figure that was never read from a sentence is `null` by construction, and a figure whose reading failed is also `null` but is accompanied by the existing `exitNote` that says why. The screen never has to guess. |
| **TRADEOFFS** | Every construction of a `RenderedFigure` changes, which is every money screen. The payload grows by a sentence per figure, and a seller's sentence can be long — the rendering must clamp to a readable length without cutting a verified span in a way that changes what it says. Two source shapes exist today (`quotedExit` and the document reader's `sources`); both must be reconciled into the new field rather than kept beside it, or the screen has two ways to say the same thing. |
| **NOTES** | The span stored is the one `verifyQuotations` accepted, character for character — never a substring selected by the UI, or the quote can drift from what was checked. For the exit figure, `quotedExit.span` is already that span and moves onto the figure. For a document reading, `sources` is already keyed by figure id and moves onto the figures unchanged; the document path is the precedent this decision follows, not a second shape to reconcile. The entry's coffee-subscription exit is currently a structured `{ kind: "fee", fee: $0.00 }` and therefore has no span; IPD 21 requires it to take the `unknown` path so the figure and the sentence agree. Verified against fixtures only until the live re-read is exercised. |
| **NOTES (built, 2026-11-10)** | Built as decided. `RenderedFigure.source: FigureSource \| null` where `FigureSource = { label, span }`; `presentFigures` takes `sources?: FigureSources` and defaults every figure to `null`. `components/CommitmentView.tsx` renders the span in a `<q>` with its attribution under the arithmetic, styled apart from it. Both older shapes were removed rather than kept beside the new one: `quotedExit` is gone from the commitment payload and `CommitmentPayload`, and the document reader's `sources` no longer leaves the API — it becomes `source` on each figure (`lib/document/read.ts`, `app/api/read/route.ts`, `app/read/page.tsx`). Each screen now says the thing once. |
| **NOTES (the long sentence)** | The tradeoffs above ask for a clamp on a long span. None was added, and the reason is that a clamp is a change to the evidence: a quote cut at 200 characters can end mid-clause and read as a different claim from the one verified. The spans this product reads are one sentence of a product description, and they render in full. If a seller ever publishes a paragraph, the fix is to show the span in a `<blockquote>` that wraps, not to truncate it. |
| **NOTES (a failed read is not a fact)** | Found live while verifying the entry: a reading that *threw* was being cached for the full ten minutes, so one 45-second timeout turned every screen into "could not be read" until the window expired. A timeout is a fact about one attempt, not about the seller. `readPublishedExit` now caches only completed readings, and serves an aged reading while a background refresh runs. Two tests in `tests/published-exit.test.ts` cover both. |
| **NOTES (a stuck read is not a lock)** | Also found live: a request that never came back held the "one reading per text" slot for the life of the process, so every later reader joined a dead request and was told the seller's terms could not be read, with no way to try again. A three-minute ceiling now releases the slot, and each attempt only ever releases its own. The slot is why the same text is never sent to the endpoint twice at once — a free endpoint measurably starves a burst (`reading-ahead.md`, NOTES (one pass, not a burst)). |

## Wiring

- `lib/commitment/present.ts` — add the field; `presentFigures` takes the verified spans it already has access to at the call sites.
- `components/CommitmentView.tsx` — render the sentence under its figure, attributed to the source label, in the same block as the arithmetic but visually distinct.
- `app/api/commitment/[orderId]/route.ts`, `app/bill/[invoiceId]/page.tsx`, `app/receipt/[orderId]/page.tsx`, `app/read/page.tsx` — pass the accepted span through instead of the separate `quotedExit`.
- Keep `exitNote` for absence: a figure with no amount and no span still has to say why.
