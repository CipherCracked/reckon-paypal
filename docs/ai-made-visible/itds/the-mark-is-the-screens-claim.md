# ITD 37 — The Mark Is the Screen's Claim

| ITD 37 — *"Pass the mark down from the screen that knows where the sentence came from, instead of inferring it from the quotation."* |  |
| :---- | :---- |
| **THE PROBLEM** | IPD 43 puts one line under a quotation: *Read by the model, checked against your text.* The renderer that draws quotations, `FigureGrid`, is used by every screen that shows figures — the item page, the receipt, the account list, the pasted-document answer. It receives a `RenderedFigure`, and a quoted figure is one with `figure.source`: a span, a label, and nothing about who found the span. The obvious rule — draw the mark whenever there is a source — is false on most screens. `lib/market/subscriptions.ts` holds `LISTED_TERMS`, curated quotes that are verbatim substrings of a listing (*"12-month BarkBox subscription"*), transcribed by a person and checked by a test, not read by a model. A curated quote and a read one reach `FigureGrid` as the same object, so the renderer cannot tell them apart, and any rule it applies to one it applies to the other. On a product whose entire argument is that every quotation is traceable to its source, a mark that appears beside text no model touched is not a styling mistake — it is the product making a false claim about its own provenance, in the one sentence that claims it. |
| **OPTIONS CONSIDERED (Decision in bold)** | 1. **`FigureGrid` takes an explicit `modelRead` prop that defaults to `false`; `CommitmentView` forwards it; `app/read/page.tsx` is the only caller that passes it, because it is the only screen whose every quotation was cut out of the text by a model.** <br> 2. Infer the mark from `figure.source` — draw it wherever there is a quotation. <br> 3. Add `readBy: "model" \| "curated"` to `RenderedFigure`, set by whoever builds the figure. <br> 4. Compute the mark on the server and carry it on the reading payload. |
| **REASONING** | The deciding factor is **what the mark is a claim about**. It is not a statement about the shape of a sentence; it is a statement about the history of a screen — this page's sentences came from a model, this page's did not. A shape-derived rule answers a question the renderer can see; a history question is only answerable where the history is known, which is the route. Passing it from there keeps the claim and the knowledge in the same place, and it means a new screen that says nothing says nothing rather than saying something wrong. <br><br> The default is the second factor. `modelRead` is off unless a caller passes it, so the failure mode of forgetting is a missing mark rather than a false one. Option 2's failure mode is the opposite, and it is the one that reaches a judge: the item page would carry *Read by the model* under a hand-transcribed quote, and a reviewer who checked `LISTED_TERMS` would find the product's central claim overstated on the busiest screen. <br><br> Option 3 is the tidiest of the wrong answers and is rejected because it threads a rendering decision through the figure type. `RenderedFigure` is built on the server, stored in a cached reading, and rendered by four components; adding a provenance field means every producer has to remember to set it, and a missing value in an old cached payload is indistinguishable from a false one. Option 4 is rejected for the same reason plus the cache: the reading outlives a recompile (ITD 29's precedent), so a payload written before the field existed arrives without it, and the default would have to be *unknown* — which is a third state on a screen that only has room for one line. |
| **TRADEOFFS** | The correctness of the mark now rests on the caller. A future screen with curated quotations could pass `modelRead` and compile cleanly, putting a false provenance claim on a screen; nothing in the type system prevents it. The guard is a comment at the prop and the two tests that pin the honest cases — `tests/commitment-view.test.tsx` asserts no mark without the prop and exactly one in the exact wording with it, `tests/read-page.test.tsx` asserts one per sourced figure on `/read`. <br><br> The mark is per-screen, not per-quotation. On `/read` every quotation is the model's, so the granularity is exact today; a future cross-screen reading that mixed curated terms with read spans would need the flag per figure, and this prop would have to be replaced rather than extended. <br><br> The prop is a second thing every caller of `CommitmentView` has to know about, and it does nothing on all but one of them. That is the cost of not putting a provenance field in the data model: one parameter on a component, against one field in a payload that is cached and rendered by four screens. |
| **NOTES** | The sentence itself lives in `lib/commitment/provenance.ts` as `READ_BY_MODEL`, so the mark cannot drift between the figure and any future place that needs to make the same claim. Its comment records the rule this document decides: the mark is the screen's claim and may never be inferred from the presence of a quotation. |
