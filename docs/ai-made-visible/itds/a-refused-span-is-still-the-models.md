# ITD 29 — A Refused Span Is Still the Model's

| ITD 29 — *"Carry the spans the server refused, capped and unparsed, and render them only through the one component that says whose words they are."* |  |
| :---- | :---- |
| **THE PROBLEM** | Verification today ends in a number: `verifyQuotations` returns `{ accepted, rejected }`, `answerReading` puts `rejected` on the reading, `/read` prints it as a clause. The span itself is dropped at the moment it is refused, which is correct for every figure and useless for IPD 32, which needs the refused sentence on a screen. Carrying it is not a neutral change. Everything else rendered on a reading is either the document's own words (quoted, verified, marked) or the product's own labels; a refused span is the only text that is *neither* — it is a model's paraphrase or invention, and the one thing it is guaranteed **not** to be is a sentence from the document. On a screen whose promise is that every quotation is in your text, an invented sentence that is styled like a quotation is not a bug in a component: it is the product's claim becoming false. The second constraint is the cache. Readings live on `globalThis` in `lib/document/reading-cache.ts` and outlive a recompile, so a payload written by this morning's build arrives this afternoon; the last time the reading shape changed it cost the reader page three of its four examples, and `tests/commitment-view.test.tsx` now pins a payload with a missing key. Any new field has to be optional at the render site or the pass breaks the demo it was built for. |
| **OPTIONS CONSIDERED (Decision in bold)** | 1. **`Quotation` carries a `verdict: "used" \| "refused"`; the reading carries `refused: ModelQuotation[]` as well as the count; `FigureGrid` never sees them and only one component renders them — the disclosure in IPD 32 — which labels each as the model's suggestion, quotes no punctuation around it, marks no words inside it, and parses nothing from it.** Capped at three spans and 300 characters each, dropped when the reading is re-run, never logged. <br> 2. Keep the count and show only the count. <br> 3. Carry the model's whole answer, including the prose summary it also returned. <br> 4. Re-ask the model on demand for the refused spans when the reader opens the disclosure. |
| **REASONING** | The deciding factor is **what makes a span refused**. It is refused precisely because it does not occur in the text, so the truth about it is exactly the label we can put on it: *the model suggested this and it is not in your document*. Nothing about it is uncertain, and nothing about it may be treated as text — so it is carried as data, rendered as a quotation of the model, and never handed to the parser. The asymmetry is the point: a span that passes the check earns the right to become a figure; one that fails earns the right to be shown as a mistake and nothing more. <br><br> The second factor is **which component is allowed to know**. `FigureGrid` and `QuotedText` exist to render the document's words; giving either of them a second kind of string with a flag is how the two eventually become indistinguishable, at 390px, in a screenshot, by a person who was not here for this decision. A separate renderer that takes only refused spans keeps the guarantee at the type level rather than in a reviewer's memory. <br><br> Option 2 is the current state and the reason IPD 32 exists: a claim of checking that the reader must take on trust. Option 3 is rejected because the summary is the model's prose about the document — it is already discarded by `guard.ts` when it contains money, and carrying it to a screen would give prose the one route to a figure that the whole schema was built to close. Option 4 is rejected because a second call is non-deterministic, slow, and would show the reader spans from a reading that is not the reading their figures came from. |
| **TRADEOFFS** | A refused span is the only unverified string the product will ever display. It cannot be checked — that is what refused means — so its safety rests on being capped, labelled, unparsed and impossible to style as a quotation; the label is carrying the entire guarantee. <br><br> Model output is retained in the server's memory for the life of a cached reading. It is the same text the model already sent, it is never written to a log or a disk, and it is dropped when the reading is recomputed — but it is a new kind of thing to hold, and a future caching change (a shared cache, a longer TTL) has to re-open this decision rather than inherit it. <br><br> The payload grows by an optional field, so every render site has to tolerate its absence — the old-payload defect from the last shape change is the precedent, and the test that pins a missing key is the model. <br><br> The cap is a judgement, not a fact: a reading with four refused spans will show three and say nothing about the fourth. Saying *"and one more"* is a sentence about our cap rather than about the document, so the count on the closed line remains the honest total. <br><br> This does not fix the ambiguity the review raised separately: verification is a literal substring check, so a span that occurs twice in a document (a repeated fee table) is verified against the right text and can be *marked* at the first occurrence. Carrying offsets would settle it, and is not affordable in this pass; the mark is a pointer, not the evidence, and the quoted span is identical at both occurrences. |
| **NOTES** | The field is additive: `ModelQuotation` gains an optional verdict and the reading gains an optional `refused` array, so an old cached payload renders as it does today — count only, no disclosure contents. `verifyQuotations` keeps its current return shape and the caller partitions, so nothing that depends on the rejection count changes behaviour. <br><br> The wording of the label is IPD 32's business, not this document's; what this document fixes is that the label exists, that it is rendered by one component, and that the refused text is never passed to `parseAmount`, `readQuotations` or `QuotedText`. |

## Built (2026-11-12)

`lib/document/refused.ts` holds the cap and the partition; `lib/document/answer.ts` puts `refused` on the reading; `components/ReadingCheck.tsx` is the one renderer. `verifyQuotations` was left alone — as written above, the caller partitions by identity (`new Set(accepted)`), which keeps the rejected count and the seller's published-text reader exactly as they were.

Two notes from the build. **The field is not rendered at all.** `RefusedSpan.field` is carried because it is part of what was refused, and never shown: `amountPerPeriod` is our vocabulary, and the screen it would appear on is the one people came to for less of it. **`refused` is optional on the server's own type too**, not only at the render site — the reading cache outlives a recompile, so a payload built before this field existed is a real object in memory, and a required field would have been a lie the compiler could not catch.
