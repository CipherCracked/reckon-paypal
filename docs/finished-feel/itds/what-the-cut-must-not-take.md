# ITD 28 — What the Cut Must Not Take

| ITD 28 — *"Use a finding-or-standing-fact test on every sentence, and pin the result in the suite by asserting where the caveat is, not merely that it is gone."* |  |
| :---- | :---- |
| **THE PROBLEM** | Cutting prose in this product is not a copy edit, because some of its sentences are the product. *Not stated* is the exit figure's answer; *we could not check what this store holds for you, this is not a statement that you have none* is the difference between an empty account and a failed scan (IPD 26); *keep this page — it is the only copy* is a warning about an irreversible act; *none of these is a total* is the reader's only statement about what it did not compute. Every one of them was added by a decision, and every one of them reads, to a person who has not read those decisions, like exactly the kind of sentence the owner asked to remove. <br><br> So the pass had no safe heuristic. A rule of *shorter is better* would have deleted the absences first, because they are the most caveat-shaped sentences in the product — and the product would then be quieter, better reviewed and wrong at the one moment it matters: when the screen has nothing to show. <br><br> The suite made this concrete. Six tests failed the moment the copy changed, each on a sentence that had been deliberately narrowed; the choice was whether to loosen them or to restate them. |
| **OPTIONS CONSIDERED (Decision in bold)** | 1. **Every sentence is sorted by one question — is it a standing fact about the store, or something this screen found? Standing facts move to the frame (IPD 29). Findings stay, shortened but never removed. Each failing assertion is rewritten to the new behaviour, and two assertions pin the caveat's position: the home page carries it exactly once at the foot, and the consent component — which renders outside the page frame in tests — does not carry it at all.** <br> 2. Delete the assertions the cut broke; the tests are about behaviour that no longer exists. <br> 3. Snapshot the rendered pages and accept the new output. <br> 4. A source-level check — grep the routes for a list of forbidden phrases. |
| **REASONING** | The deciding factor is that **a test in this suite is the only place a guarantee about honesty is written down in a form that fails**. *Absence is stated as absence* is not enforced by a type; it is enforced by `expect(exit).toHaveTextContent(/not stated/i)`. An assertion deleted in a polish pass is a guarantee deleted in a polish pass, and the pass would look like a tidy-up while it happened. Rewriting it to the new sentence keeps the guarantee and records that the sentence changed on purpose. <br><br> The second factor is that **the decision being made was about position, so the position is what gets asserted**. *The caveat exists* was already true nine times over; *the caveat exists once, at the foot, and nowhere else* is the change. Asserting `getAllByText(/sandbox store: …/)).toHaveLength(1)` fails on both halves — a missing line and a second copy — which is exactly the failure mode this pass exists to prevent coming back. The consent assertion is its mirror image: it renders outside the frame, so the sentence must be absent there, and if someone reintroduces it in the component it fails. <br><br> Option 2 is rejected because the tests that broke were the ones doing work. Option 3 replaces a statement about behaviour with a picture of output: it fails on every legitimate wording change and says nothing about which guarantee moved. Option 4 checks the spelling of the apology rather than the pattern that produced it — the next screen would say *this is a demonstration environment*, which no list of phrases contains. <br><br> One sentence needed adjudication under the rule: *nothing has been charged* on the entry. It is a standing fact about the store and it also stayed, because on that screen it is a statement about what the screen just did, and it sits under the figures rather than in the frame. The rule is a test to apply, not a mechanical sort, and this is the documented exception. |
| **TRADEOFFS** | Several assertions now match exact strings, so the next legitimate copy change breaks tests again. That is the cost of testing the sentence rather than the concept, and it is paid knowingly: this product's sentences are its interface, and a silent rewording is the failure being guarded against. <br><br> The once-on-page assertion only holds for pages that render through `Page`. A screen that bypasses the frame is not covered, and the consent test covers that case only because it is the one component that renders alone. <br><br> The rule lives in a document and in two tests, so a new screen can still add a tenth apology in fresh wording and pass. Nothing catches the pattern until someone applies the test by hand. |
| **NOTES** | Absence, failure and provenance statements that survived, and where they live: the exit figure's *Not stated* (`FigureGrid`), the scan-failed line (`RecordHome`), *keep this page — it is the only copy* (`CommitmentRecord`), *none of these is a total* and the example provenance (`/read`), *check the amount with them* (the bill), and *this is today's charge, not the total across the term* (the consent screen). |
