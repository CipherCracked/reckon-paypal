# ITD 13 — App Shell

**Status:** Adopted (2026-11-07) — not yet built
**Date:** 2026-11-07
**Answers:** Problem tree Q4 of `../intro.md` — *how does a person move through it, and where does the journey end?*
**Serves:** IPD 15 (a persistent frame naming the service, a named back target everywhere) and IPD 14 (identity in a header, not in page copy).

| *"Use a shared root layout with an explicit back target to give every route a place, without moving page content into a client component."* |  |
| :---- | :---- |
| **THE PROBLEM** | `app/layout.tsx` renders `<body>{children}</body>`: no landmark, no skip link, no service name, no footer. Eight routes therefore have no shared frame, and five of them (`/product`, `/consent`, `/bill`, `/receipt`, `/shop`) have no link that leaves them. The frame cannot be derived from the request: a server component has no trustworthy history, and a back link that guesses is worse than none. The frame also must not turn the app's server-rendered pages into client components, because the entry's figures have to be in the first paint without JavaScript (ITD 16). |
| **OPTIONS CONSIDERED (Decision in bold)** | 1. **The root layout renders a skip link, a header carrying the service name and a link home, and a footer; each page declares its own back target, rendered by one small server component above the heading.**<br>2. Each page renders its own header and footer, with no shared layout.<br>3. A client navigation bar that derives position from `usePathname` and offers active states.<br>4. No shell; the browser's own controls are the navigation. |
| **REASONING** | App Router layouts persist across navigation and stay server components, so the frame costs no client JavaScript and exists in one place — the only place where a landmark can be wrong for every route at once, which is also the only place where it can be fixed once. A back target cannot be derived on the server: there is no referrer to trust and no history, and `router.back()` can leave the app or return to a document that no longer exists after the PayPal redirect (ITD 14). The page itself knows where it came from, so the page declares it; a missing declaration shows as a missing link and is testable. Option 3 would put the frame into a client component for an active-state highlight the product does not need — there is exactly one frame item today, the home link — and would pull the entry's rendering client-side. |
| **TRADEOFFS** | Every new route must declare a back target; an omission is a silent gap unless a test covers each route. The header consumes vertical space on a phone, where the figures are closest to the fold. A shared layout is a single point of failure: a mistake in it reaches every screen. |
| **NOTES** | `<main id="main">` is the skip target and the skip link is the first focusable element. `aria-current="page"` only where a frame item matches the current route — today that is the home link, when on `/`. Focus is not moved on navigation except where a page already moves it deliberately (the recognition check). The footer carries the service name and the licence line only — no status line and no link to the judge brief, which lives outside the product (IPD 14, IPD 16). The record screen declares no back target: it is the end of the journey and offers its two ways on explicitly (IPD 15). The skip link targets `#main`, which this component renders. |
